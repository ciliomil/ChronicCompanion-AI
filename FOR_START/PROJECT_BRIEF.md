# PROJECT_BRIEF.md

## 项目名称
面向糖尿病老年用户陪伴助手的个性化长期记忆机制研究

## 项目目标
本项目旨在实现一个面向糖尿病老年用户的陪伴型大模型助手原型，重点验证“个性化长期记忆”是否能够提升跨 session 连续性、个性化聊天质量和温和建议的适配性。

本项目不是完整医疗系统，而是一个科研原型。核心任务不是堆叠功能，而是围绕长期记忆的提取、更新与调用，完成 baseline、改进方案和实验验证。

## 核心场景
### 主场景
- 基于历史记忆的个性化聊天

### 辅场景
- 基于用户情况的温和提醒或建议

## 研究重点
项目聚焦以下关键技术问题：
- 长期记忆的提取
- 长期记忆的更新
- 长期记忆的调用
- 面向用户需求的检索
- 个性化生成与医疗安全边界的平衡

## 方案概览
项目采用三层长期记忆结构：
1. **底层：原始交互层**
   - 保存原始对话文本
   - 做基础编号与分块
   - 为上层抽取和回答生成提供可回溯证据

2. **中层：用户记忆层**
   - 组织与用户相关的事件和“需求-方案”轨迹
   - 重点保留时间信息、用户隐含需求、AI 解决方式、用户反馈等

3. **顶层：用户画像层**
   - 形成较稳定但可持续更新的用户画像
   - 包括基本背景、近期状态、主要需求和偏好结构

## 原型目标
第一阶段希望搭建一个最小可运行原型，具备以下能力：
- 能进行基本多轮对话
- 能写入和读取三层记忆结构
- 能基于当前 query 和用户画像做需求推测
- 能从中层记忆中检索相关历史线索
- 能生成基础个性化回答
- 能进行基本风险分级与安全约束

## Baseline
项目至少包含两个对照版本：
- **Baseline 0：无长期记忆**
- **Baseline 1：通用向量检索式长期记忆**

## 改进方向
改进方案为三层长期记忆结构，重点验证：
- 相比简单历史拼接或向量检索，是否更能理解“当前这个用户需要什么”
- 是否能更好利用近期状态、历史事件和偏好轨迹
- 是否能提升建议适配性与跨 session 连续性

## 数据来源与限制
项目不使用真实患者隐私数据。实验数据采用：
- 模拟用户画像
- 合成长期时间线
- 多 session 对话数据

## 明确不做的内容
以下内容不在当前原型范围内：
- 不做完整医疗问诊系统
- 不输出诊断结论
- 不提供药量调整、治疗替代等高风险医疗建议
- 不以复杂前端界面为主要成果
- 不优先追求大而全，而优先保证研究问题清晰、结构合理、实验可做

## 当前开发原则
- 优先搭建清晰、可扩展、可实验的项目骨架
- 优先模块边界清楚，而不是把所有逻辑堆在一个文件
- 优先实现最小可运行原型，再逐步细化事件抽取、需求推测和画像更新
- 所有关键模块尽量支持 mock / stub，方便后续实验替换
